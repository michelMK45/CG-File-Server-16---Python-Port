# Triage a bug report

Goal: name the mechanism and the evidence before touching code. Claude never sees the game; the log
and the user's description are the only ground truth. Answer the user in Spanish.

## 1. Collect (ask only for what is missing)

- App version (`server16_py/__init__.py` on their build; old reports say e.g. "1.7.1"), source build or exe.
- Which install/mod (vanilla, FIP x.y, Rev Mod version), screen mode, Half Length if chants/entrance.
- The log: `runtime/server16.log` (+ `server16.previous.log`); where forum logs are saved is in
  `CLAUDE.local.md`. Overlay issues: also `%TEMP%\cgfs16_overlay.log`.
- Pass the log path to the `log-analyst` agent (never read a big log in the main context).
- **Crash / name not found / weird STAD 176|261:** first ask whether **Setup** was run and
  **Regenerate BH** pressed for that exact version, and whether `FSW/settings.ini` was generated by the
  app (not hand-made/copied). That was the real cause of the 2026-10-04 crash.
- Module switches in their `settings.ini` `[Modules]` (an explicit `0` is honoured).

## 2. Map symptom → first grep → doc

| Symptom | First log evidence | Doc |
|---|---|---|
| Custom stadium name not on pre-match screen | `fast watch found/patched` before `TV/bumper`; `isolated utf-8 occurrence`; `failed isolation`; `retry stopped`; `Stad name write skipped` | `docs/bugs-scoreboardstdname.md` |
| Crash after match / at Kick-Off with name module on | `scan attempt` / `replaced ... at 0x` on FluxHub/SelectTeam/SideSelect; `Game process ended` | same + bisect there |
| Chants never start / "Awaiting home chants" | `Left match for` right after KickOffHub (SkillGamePause loading screen) | `docs/bugs-misc.md` |
| "Waiting for kick-off" stuck | `Pre-match Support guard released` (which path), `Chants live match`, `Chants clock:` | `docs/bugs-entrance.md` |
| Anthem plays in a menu / after Abandon / not on Restart | `Page transition` names, `Team entrance armed/skipped/fade-out` | `docs/bugs-entrance.md`, `docs/team-entrance.md` |
| Stadium textures green/blue | was the previous match vanilla? (known unfixed) | `docs/stadium-slots.md` |
| Stadium reloads after Team Management/Settings | `KickOffHub revisit`, `Match preparation ended` | `docs/stadium-slots.md` |
| Goalpost/net/net color stuck from earlier stadium | `Goalposts applied ... -> [files]`, `Net mesh applied`; stale = "two loads ago"? | `docs/bugs-goalpost.md` |
| Ball/referee/wipe/adboard not visible | `Applying runtime ... LEAGUE=`, `pack id X -> Y` (pack id must be the engine league id `TLEAGUE`) | `docs/module-map.md` (`match_asset_ids.py`) |
| F12 doesn't open / reopens / closes itself | DLL log `menu=`; `D3D menu opened/closed`; `Stadium picker abandoned` | `docs/bugs-overlay-input.md` |
| Key "acts late" | that key also bound *held* to another action (TAP mode, by design) | same |
| Kits > Team mix not applied | block header in Portuguese / `KitMixer` process running (Dinei's tool overwrites blocks) | `docs/kit-mixer-and-extractor.md` |
| Gamepad double input / driver buttons | `HidHide`, `Gamepad driver` lines | `docs/gamepads-hidhide-vigembus.md` |
| Memory read errors spam | context-read lines | `docs/bugs-misc.md` |

For a log over a few hundred lines, delegate: `log-analyst` agent with the symptom, the time window and
the keywords from the table. Ask it for a timeline, not a dump.

## 3. Conclude honestly

- State: mechanism, the log lines that prove it, and what is still inferred. If two hypotheses fit,
  say which log line would separate them and ask for it.
- Don't call it a "known limitation" without comparing against a working log (the 2026-10-26 FIP 9.2
  case was our search window, not the game). Don't present a hardening change as the fix.
- Memory writes: no new address/footprint without the user's Cheat Engine confirmation
  (`/ce-check` skill).
- If the user wants a forum reply, draft it short, in the reporter's language, with the exact
  test steps and log lines to send back.
- Then fix (if asked) and finish with `/wrap-up`.
